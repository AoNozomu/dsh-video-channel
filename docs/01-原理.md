# 01 · 这套东西的原理

## 一句话

**把视频拆成「画面」和「台词」两条独立的路：画面按变化去重、台词一秒不落地认出来。**

---

## 为什么要拆

看一条视频，模型需要两种信息：

| 需要知道 | 从哪来 | 本来怎么做 | 问题 |
|---|---|---|---|
| 说了什么 | 台词 / 字幕 | OCR 画面上的字 | 一边看图一边认字，图和字混在一起 |
| 看到什么 | 画面 | 分镜图 | 一图只能几格，长视频看不过来 |

原插件把两者合在「分镜图」里：一帧一帧抽，拼成图让人看。
**但字幕和画面变化的节奏完全不同** ——

```
画面：一张脸能停 7 秒不动（7 秒里 7 帧几乎一样）
台词：7 秒里换了 5 句（每句都不能漏）
```

按画面节奏抽 → 台词会漏；按台词节奏抽 → 图会大量重复。
所以**拆开**：画面按「变没变」决定留不留，台词按「每帧都认」决定取不取。

---

## 画面这条路：相邻帧去重

```
第 1 帧  → 留着（第一帧总要留）
第 2 帧  → 和第 1 帧比：差异 1.2%  < 阈值 6  → 丢掉
第 3 帧  → 和第 1 帧比：差异 8.4%  >= 阈值 6 → 留着，更新「上一张」
…
```

**「差异」怎么算**：不是逐像素比（太慢），而是**每 97 个像素采一个点**（97 是质数，
避开规则图案），算 R/G/B 三个通道的平均绝对差，归一化到 0-100。

```js
for (let i = 0; i < a.data.length; i += 97 * 3) {
  sum += |a[i]-b[i]| + |a[i+1]-b[i+1]| + |a[i+2]-b[i+2]|;
}
return (sum / (n * 3 * 255)) * 100;   // 0-100
```

**阈值 `--diff 6` 是实测调出来的**：
- 太小（2-3）→ 光照轻微变化也留，省不下来
- 太大（15+）→ 真变化也丢，画面跳帧

**实测去重率 54%**（1560 帧 → 710 格）。

## 台词这条路：整帧 OCR + 按位置切割

### 为什么不能只裁字幕条再 OCR

实测过，**RapidOCR 认细长条会直接返回 `None`**：
```
960×119 的字幕条   → (None, None)   ← 一个也认不出
1280×720 的整帧    → 「阿维达」✓   ← 认得准
```

RapidOCR 的检测模型需要「上下文」，一条孤零零的字幕它判断不出是文字。

**所以：喂整帧，认完之后按坐标丢掉上面的部分。**

```
整帧 960×540
   ↓ OCR
┌────────────────────────┐
│ 4K修复播放室 (y=26)     │ ← 水印
│ 关注微博@... (y=22)     │ ← 广告
│ ...                    │
│ acasaka (y=429, 79%)   │ ← 场景里的招牌，要丢
│ 我们的人呢 (y=496, 92%) │ ← 真字幕，要留
└────────────────────────┘
   ↓ 只留 y > 高 * 0.80
「我们的人呢」✓
```

详见 `02-字幕区域.md`。

---

## 认字这条路：为什么换 RapidOCR

原插件用 Windows 自带 OCR（`Windows.Media.Ocr`）。它能跑、不要钱、不要模型，
但对**动画字幕**（小字、白字黑边、半透明背景）质量不够：

| | Windows OCR | RapidOCR |
|---|---|---|
| 「水龙头在灯管下滴答」 | 「水龙头疒下谪」✗ | ✓ |
| 「这顿骂我跑不掉」 | 「辶顿骂我跑不掉」✗ | ✓ |
| 「目标已控制箱子到手」 | （读不出）✗ | ✓ |
| 稳定性 | 同一帧时好时坏 | 稳定 |
| 速度 | 60 秒 / 3 分钟视频 | 110 秒 / 3 分钟视频 |

**慢一倍，但准确率从「70% 靠猜」变成「95% 能读」。** 这个交换值得。

⚠️ **装的坑**：`rapidocr-onnxruntime` 会把 numpy 升到 2.x，把 `onnxruntime 1.18`
（用 numpy 1.x 编译的）搞崩。如果那个 Python 环境还跑着语音服务，**语音就挂了**。
→ **必须单独建 venv**（见 patches/NOTES.md）。

## 台词去重：相邻相似合并

字幕一句话会停留 1-3 秒，每秒认一次就是 2-3 条重复（而且每遍认出来的字略有不同）。

```js
// 相邻两帧，时间差 ≤3 秒，且「字重叠比例」≥55% → 认为是同一句
function similar(a, b) {
  const A = bigrams(a), B = bigrams(b);       // 每两个字取一个二元组
  let inter = 0;
  for (const g of A) if (B.has(g)) inter += 1;
  return (2 * inter) / (A.size + B.size) >= 0.55;   // Dice 系数
}
// 组里选最长的那条（通常漏字最少），时间取最早一帧
```

**为什么用二元组而不是逐字比**：OCR 错一个字时，逐字比相似度掉太快；
二元组对单字错误更宽容（「在灯管下滴」vs「疒下谪」仍能认出是同一句）。

## 成本

一整集 26 分钟：

```
分镜图：45 张（全读约 45K token，实际只挑 8 张看）
台词：  416 条 / 6311 字符 ≈ 3.8K token
─────────────────────────────────────
实际用法：~11K token ≈ 0.011 元（缓存未命中）/ 0.001 元（命中）
```

**关键**：先读台词拿剧情（便宜），只在需要看「台词说不出来的东西」（表情、动作、
场景）时才读图。

---

## 完整流程

```
视频文件
   │
   ├─ ffmpeg 每秒抽一帧（960 宽，给 OCR）
   │      │
   │      └─ RapidOCR 认整帧 → 按 y>80% 留字幕 → 相邻相似合并
   │            │
   │            └─ subtitles.txt  [秒] 台词
   │
   ├─ ffmpeg 每秒抽一帧（480 宽，给拼图）→ 相邻帧差异去重
   │      │
   │      └─ composeSheet 每 16 格拼一张
   │            │
   │            └─ sheet-001.png … + index.json（每格的秒数）
   │
   └─ where.mjs 把两边对上：某句台词 → 哪张图哪一格
```
