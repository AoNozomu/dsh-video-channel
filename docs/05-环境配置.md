# 05 · 环境配置（完整版）

按这个配，一次跑通。**每一条都是实测过的**，不是抄文档。

---

## 一句话要求

```
Node 18+  ·  Python 3.9+（独立环境）  ·  ffmpeg 4.0+  ·  磁盘 ≥1 GB
```

**平台**：Windows 10/11 完整可用。Linux / macOS 可用，但原插件的
`video_read`（读幻灯片文字）依赖 Windows 自带 OCR，那两个平台用不了 ——
**本通道（scan-video / ocr_frames / where）跨平台，不依赖 Windows OCR。**

---

## 1. Node.js

| | |
|---|---|
| **要求** | **18 或更高**（用到顶层 await、`node:` 前缀 import、`crypto.createHash`） |
| **实测** | **v24.16.0** |
| **怎么查** | `node --version` |
| **装** | https://nodejs.org/ （LTS 版） |

**为什么需要 18+**：`upstream/src` 里用了 `fileURLToPath`、动态 import、
以及 ESM 的顶层 await。Node 16 会报 `Cannot use import statement outside a module`。

```bash
cd upstream
npm install          # 原插件的依赖（主要是 sharp 之类的图像/媒体处理）
```

**npm install 会装多少**：约 80-150 MB（`node_modules/`）。如果只想跑本通道，
实际上只需要 `upstream/src` 里的几个纯 JS 模块，但 `npm install` 更省心。

## 2. Python（给 RapidOCR 用）

| | |
|---|---|
| **要求** | **3.9 或更高** |
| **实测** | **3.14.5**（另在 3.10.7 上也验证过） |
| **装在哪** | ⚠️ **必须独立 venv**，见下面「为什么必须独立」 |
| **磁盘** | **约 263 MB**（含 numpy / onnxruntime / opencv / 模型） |

### 建环境

```powershell
# Windows
C:\Users\<你>\AppData\Local\Programs\Python\Python314\python.exe -m venv E:\ocr-env
E:\ocr-env\Scripts\python.exe -m pip install rapidocr-onnxruntime

# Linux / macOS
python3 -m venv ~/ocr-env
~/ocr-env/bin/pip install rapidocr-onnxruntime
```

### 实测装出来是什么版本

```
rapidocr-onnxruntime  1.2.3      ← pip 自己选的
numpy                 2.5.4
onnxruntime           1.31.1
Pillow                13.0.0
opencv-python         5.0.0.93
Shapely               2.2.0
```

**不需要锁版本** —— 用最新即可，实测这套组合工作正常。

### ⚠️ 为什么必须独立 venv（这条最要命）

`rapidocr-onnxruntime` 把 numpy 升到 **2.x**。但很多环境里的 `onnxruntime 1.18`
是**用 numpy 1.x 编译的**，升上去直接崩：

```
A module that was compiled using NumPy 1.x cannot be run in NumPy 2.2.6
```

我们已经因为这件事把**语音服务搞挂过一次**（CosyVoice 用 onnxruntime）。
所以：**凡是有 onnx 模型在跑的环境，都不要往里装 rapidocr。**

**已经搞崩了怎么救**：
```powershell
# 把 numpy 降回去
<那个venv>\Scripts\python.exe -m pip install "numpy==1.26.4" --force-reinstall
# 把 rapidocr 卸掉
<那个venv>\Scripts\python.exe -m pip uninstall -y rapidocr-onnxruntime opencv-python pyclipper Shapely
```

### 网络：第一次要下模型

`pip install` 装的是**代码**，模型（约 15 MB）在**第一次运行时**才下载。
下载到 `~/.cache/rapidocr` 或类似位置。

**如果没网**：先把模型下好放进缓存目录，或者换用 `PaddleOCR` 的离线模型包。
**校园网/代理环境**：pip 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 会快很多。

## 3. ffmpeg

| | |
|---|---|
| **要求** | **4.0 或更高**（用到 `crop` / `scale` / `fps` / `-ss` 精确定位） |
| **实测** | **2022-10-30-git**（gyan.dev essentials build） |
| **位置** | 三选一，见下 |

三种放法：

```powershell
# a) 用原插件自带的（推荐，省事）
E:\dsh-video-vision\vendor\bin\ffmpeg.exe
# → 命令行加 --ffmpeg "E:\dsh-video-vision\vendor\bin\ffmpeg.exe"

# b) 环境变量
$env:DSH_FFMPEG_PATH = "E:\...\ffmpeg.exe"

# c) 加进 PATH（最省事，之后不用传参）
```

**Windows 下载**：https://www.gyan.dev/ffmpeg/builds/ （essentials 版够了，约 77 MB）
**Linux**：`apt install ffmpeg` / `dnf install ffmpeg`

**要不要 ffprobe**：本通道用 `ffmpeg -i` 的输出解析时长，**不需要 ffprobe**。
但如果 `--end` 不给，脚本会优先找 ffprobe，找不到再退回 `ffmpeg -i`。

## 4. PowerShell 执行策略（Windows 特有的坑）

第一次跑 `install.ps1` 可能报：

```
无法加载文件 install.ps1，因为在此系统上禁止运行脚本
```

**解法**（不用改系统设置，只对这一次生效）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

**别做**：`Set-ExecutionPolicy Unrestricted`（改系统级设置，不安全）。
文档里所有命令都用 `-ExecutionPolicy Bypass` 的写法。

## 6. 完整检查脚本

跑这个，一次看清环境齐不齐：

```powershell
# 存成 check-env.ps1，或直接粘进 PowerShell
Write-Host "=== Node ==="
node --version
Write-Host "`n=== ffmpeg ==="
if ($env:DSH_FFMPEG_PATH) { & $env:DSH_FFMPEG_PATH -version 2>&1 | Select-Object -First 1 }
else { ffmpeg -version 2>&1 | Select-Object -First 1 }

Write-Host "`n=== Python (OCR) ==="
$ocrPy = "E:\ocr-env\Scripts\python.exe"      # ← 改成你的路径
if (Test-Path $ocrPy) {
  & $ocrPy --version
  & $ocrPy -c "import rapidocr_onnxruntime, numpy, onnxruntime; print('  rapidocr OK'); print('  numpy', numpy.__version__)"
} else {
  Write-Host "  没找到 $ocrPy"
}

Write-Host "`n=== upstream 模块 ==="
foreach ($m in @('frames.js','sheet.js','png.js','media.js')) {
  $p = Join-Path $PSScriptRoot "upstream\src\$m"
  if (Test-Path $p) { Write-Host "  [OK] $m" } else { Write-Host "  [X] $m 缺失" }
}
```

## 7. 常见环境错误对照

| 报错 | 原因 | 解法 |
|---|---|---|
| `Cannot use import statement outside a module` | Node < 18，或没 `type: module` | 升 Node |
| `找不到 ffmpeg` / `spawn ENOENT` | ffmpeg 不在 PATH | `--ffmpeg` 或 `DSH_FFMPEG_PATH` |
| `找不到 OCR 的 python` | `--ocr-python` 指错了 | 确认路径存在，或先建 venv |
| `A module compiled using NumPy 1.x cannot be run in NumPy 2.x` | 装的 venv 里有旧 onnxruntime | **换独立 venv**（见 2） |
| `ModuleNotFoundError: rapidocr_onnxruntime` | 装到别的 python 上了 | `<venv>\Scripts\python.exe -m pip install ...` |
| `无法加载文件 install.ps1` | 执行策略 | 加 `-ExecutionPolicy Bypass` |
| `SyntaxError: Invalid or unexpected token` | 文件被写成带 BOM 的 UTF-8 | 用编辑器存成「UTF-8 无 BOM」 |
| `ffmpeg: Unknown filter` | ffmpeg 版本太老 | 换 4.0+ |

## 8. 性能参考（本机实测）

```
CPU: 普通桌面机（未记录具体型号）
内存: 16 GB

26 分钟视频 / 1560 秒 / step=1
  抽帧（960 宽）      约 60 秒
  OCR（RapidOCR）    约 10 分钟   ← 主要耗时
  抽帧 + 去重（480）  约 3 分钟
  拼图（45 张）       约 2 分钟
  ─────────────────────────
  合计               约 16 分钟

RapidOCR 速度：约 0.37 秒/帧
Windows OCR 对比：约 0.15 秒/帧（但准确率低得多）
```

**想加速**：
- `--step 2`（每 2 秒一帧）→ OCR 时间减半，但可能漏台词
- `--ocr-width 720` → 快一点，但小字幕可能认不出
- 多进程跑 OCR（`ocr_frames.py` 目前是单进程，可以改成 batch 并发）
