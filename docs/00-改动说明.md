# dsh-video-channel

**把一条视频看成「能读的文字 + 能看的分镜」，而不是一堆图片。**

给 DSH / DeepSeek 这类工具型 agent 用的视频读取通道：
画面按变化去重，台词逐秒全部读出来，两者用时间码对齐。

---

## 这套东西解决什么

原来的分镜工具（`video_storyboard`）一次只出一张图（≤28 格），而且格子放在镜头切换点。
面对「看完整一集 26 分钟」这种需求：

- 得连跑上百次
- 长镜头中间发生的事看不到
- 分镜图上根本读不清字幕

**本通道拆成两条独立的路：**

| | 处理后 | 产出 |
|---|---|---|
| 画面 | 相邻帧差异小的丢弃（省 54%） | 45 张分镜图，每格带编号 |
| 台词 | 每一秒的那一帧都 OCR，一句不落 | 416 条台词，带 `[秒]` 时间码 |

**实测一整集（26 分钟）**：
```
1560 帧 → 710 格 → 45 张图
416 条台词 / 6311 字符
剧情可以完整复述，人物关系能对上
实际 token 消耗 ~11K（≈0.01 元）
```

## 环境要求

```
Node 18+  ·  Python 3.9+（独立 venv）  ·  ffmpeg 4.0+  ·  磁盘 ≥1 GB
```

| 组件 | 要求 | 实测 |
|---|---|---|
| **Node** | 18+（用到 ESM / 顶层 await） | v24.16.0 |
| **Python** | 3.9+，**必须独立 venv** | 3.14.5 / 3.10.7 |
| **ffmpeg** | 4.0+ | 2022-10-30 gyan build |
| **磁盘** | ocr-env 263 MB + ffmpeg 77 MB + 每集产物 30-60 MB | — |

**平台**：Windows 完整可用。Linux / macOS 也可用本通道
（`scan-video` / `ocr_frames` / `where` 都不依赖 Windows OCR；
只有 upstream 的 `video_read` 读幻灯片功能需要 Windows）。

⚠️ **RapidOCR 必须装进独立 venv** —— 它会把 numpy 升到 2.x，
把用 numpy 1.x 编译的 `onnxruntime` 搞崩（我们因此搞挂过一次语音服务）。

**完整的环境说明、错误对照、性能数据 → [docs/05-环境配置.md](docs/05-环境配置.md)**

## 快速开始

### 1. 准备依赖

```bash
# ffmpeg（三选一）
#   a) 原插件里已有：直接 --ffmpeg 指过去
#   b) 系统 PATH 里有
#   c) 下载放 upstream/vendor/bin/

# RapidOCR（单独环境！别污染有 onnxruntime 的 venv）
<某个 python> -m venv E:\ocr-env
E:\ocr-env\Scripts\python.exe -m pip install rapidocr-onnxruntime

# 原插件的 node 依赖
cd upstream && npm install
```

### 2. 装进 upstream

```powershell
# Windows
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1

# Linux / macOS
chmod +x install.sh && ./install.sh
```

它干三件事：把 `patches/*.mjs` 和 `*.py` 复制进 `upstream/bin/`、
检查 import 路径、跑一次语法检查。

> **没装也行**：`install.ps1` / `install.sh` 干的就是复制三个文件 + 语法检查。
> 你也可以手动 `cp patches/*.mjs patches/*.py upstream/bin/`，结果一样。

> ⚠️ `install.sh` 是照 `install.ps1` 一一对应写的（cp + `node --check`），
> **作者只在 Windows 上实测过**，Linux/macOS 没跑过。有问题请开 issue。

### 3. 扫一条视频

```bash
cd upstream
node bin/scan-video.mjs "D:\video.mp4" --start 0 --end 1600 --step 1 \
  --per-sheet 16 --cols 4 --width 480 --ocr-width 960 --bottom 0.80 \
  --ocr-python E:\ocr-env\Scripts\python.exe --out out/ep1
```

### 4. 先读台词

```bash
head -60 out/ep1/subtitles.txt
```

**剧情基本就清楚了。** 只在需要看「台词说不出来的东西」（表情、动作、场景）时才读图。

### 5. 认人（必须）

```bash
# 定位：这句话落在哪张图哪一格
node bin/where.mjs out/ep1 --grep "米格尔"
# [181s] 米格尔集中精神   → sheet-004.png 第 62 格

# 放大看脸（别用分镜图猜！）
ffmpeg -ss 181 -i "D:\video.mp4" -frames:v 1 -vf "scale=1100:-1" -y check.png
```

详见 **[docs/03-认人规矩.md](docs/03-认人规矩.md)**。

## 关键参数

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--step` | 1 | 只看大概可以用 2-3 |
| `--per-sheet` / `--cols` | 16 / 4 | 想每格更大 → `--per-sheet 9 --cols 3` |
| `--width` | 480 | 分镜格宽度，越大越清楚、token 越贵 |
| `--ocr-width` | 960 | **别降到 480**，字幕会认不出 |
| `--bottom` | 0.80 | 字幕位置偏高的番 → 0.70；误收场景文字 → 0.85 |
| `--diff` | 6 | 保留率 <30% 调小，>80% 调大 |
| `--no-subtitle` | — | 只要分镜图、不要台词时加 |

## 成本参考

```
26 分钟一集
  抽帧 + OCR + 拼图    约 16 分钟（本机）
  台词（全读）         3.8K token
  分镜图（挑 8 张看）   8K token
  ───────────────────────────
  合计                ~11K token ≈ 0.011 元（缓存未命中）
```

**对比**：直接读 45 张分镜图 = 45K token，是这条路的 4 倍，而且**读不出台词**。

## 已知限制

| 限制 | 说明 |
|---|---|
| **认不出脸** | 分镜图 480×270，人物长相靠放大单帧看，别猜 |
| **画面内嵌对白气泡挡不住** | 漫画风对白在画面中部，会被当成台词 |
| **片尾自动播下一集** | `--end` 要掐准，否则混进下一集台词 |
| **只认硬字幕** | 内嵌字幕轨（.srt/.ass）不走 OCR，建议先 `video_probe` 看有没有 |
| **动画字幕质量依赖分辨率** | 源太糊（<720p）时识别率会掉 |
| **RapidOCR 慢** | 约 0.37 秒/帧，比 Windows OCR 慢一倍（换准确率） |

## 上游插件

`upstream/` 来自 [dsh-video-vision](https://github.com/) —— 提供：
- 视频探测（时长/分辨率/字幕轨）
- 单张分镜（按镜头切，`video_storyboard`）
- 局部放大（`video_zoom`）
- 文字读取（`video_read`，走 Windows OCR）

**本通道是它的补充，不是替代。** 短片段、只看几眼 → 用 `video_storyboard`；
要看完整一集、需要台词 → 用本通道。
